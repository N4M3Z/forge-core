Work follows one pipeline, not three independent steps. Enable Entire first so the session and its checkpoint history are captured. Do the work in jj (colocated with git; bookmarks become the branches that get pushed). Then commit while the user is present, so the commit is a GPG-signed git artifact that carries Entire's session history. Pushing without Entire enabled, or trying to sign unattended, breaks the chain.

Sign with GPG — the active method here (`gpg.format=openpgp`, YubiKey OpenPGP + pinentry-mac). SSH-with-FIDO2 is only the documented fallback, not the default. A `gpg: signing failed: Timeout` on a commit or `jj git push` means pinentry could not prompt from a non-interactive shell, not that the method is wrong: export `GPG_TTY`, let pinentry-mac raise the PIN dialog (the user enters the PIN and touches the YubiKey), or have the user run the push from their own terminal. jj signs on push via its gpg backend and re-signs rebased descendants automatically. Never switch to SSH signing or disable signing to get past a timeout.
