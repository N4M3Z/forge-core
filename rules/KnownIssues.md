Do not symlink plugins into the cache — Claude Code periodically wipes `~/.claude/plugins/cache/`.

macOS TCC permissions are separate from Claude Code sandbox and permission settings: EventKit tools (`ekctl`) need their own TCC grant even when the command itself is allowed.

Subagents spawned with `mode: 'auto'` cannot write to git submodule paths even with `bypassPermissions`. Symptom: agent reports completion but no files were created. Workaround: do the writes from the parent session, or accept the permission prompt manually when it surfaces.

Homebrew's `pip3` on macOS enforces PEP 668 strictly — `pip3 install`, `pip3 install --user`, and `pip3 install --break-system-packages` all fail with "No virtual environment found." Use `uv venv <dir>` to create an isolated environment, then `uv pip install --python <dir>/bin/python <package>`. Don't keep retrying pip flags; the wrapper rejects all of them by design.

A session created with `/branch` and then moved with `/cd` keeps writing its transcript in the original project directory, while cwd-derived consumers (Entire's turn-end hooks) look under the new one. Symptom: every turn ends with a non-blocking `transcript file not found` Stop-hook error and session capture silently stops. Fix: restart the session from the new directory (fresh session id, transcript in the right place). Never patch around it inside `~/.claude/projects` — no symlinks or file moves in harness internals.

The claude-in-chrome `navigate` tool force-upgrades `file://` URLs to `https://`, breaking local-file preview. To preview a local HTML file, serve its directory with `python3 -m http.server <port> --bind 127.0.0.1` and open `http://127.0.0.1:<port>/file.html`. After scrolling, read rendered state via `javascript_tool` (`getComputedStyle`, `textContent`) rather than screenshots, which can lag the paint.

Headless `Google Chrome --headless --screenshot` enforces a 500px minimum window width. A capture requested below 500px renders the page at 500px but crops the image to the requested width, so a correct layout looks clipped on the right. Screenshot at 500px or wider, and confirm horizontal overflow by measuring `document.documentElement.scrollWidth` against `window.innerWidth` inside the page rather than trusting the crop. The Chrome binary and its profile dir are blocked under the Bash sandbox (`bootstrap_check_in`, `ProcessSingleton` "Operation not permitted"); run it with `dangerouslyDisableSandbox` and a fresh `--user-data-dir`. It may not self-exit in `--headless=new`, so use old `--headless` with `--virtual-time-budget`, or background it and kill the pid once the PNG appears.
